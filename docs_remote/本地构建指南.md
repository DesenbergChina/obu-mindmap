# Obu Mindmap `main.js` 本地构建指南

本文说明如何从 `obu-mindmap` 源代码构建一个可以被 Obsidian 使用的生产版 `main.js`。

仓库：

```text
https://github.com/DesenbergChina/obu-mindmap
```

---

## 1. 构建流程

项目的实际构建链路为：

```text
src/main.ts
    │
    ├── TypeScript 类型检查
    │
    ▼
tsc --noEmit
    │
    ▼
esbuild
    │
    ├── bundle
    ├── CommonJS
    ├── ES2021
    ├── tree shaking
    ├── minify
    │
    ▼
main.js
```

最终生成：

```text
obu-mindmap/
├── main.js            ← 构建产物
├── manifest.json
├── styles.css
├── package.json
├── src/
└── ...
```

其中真正提供给 Obsidian 使用的 JavaScript 文件就是：

```text
main.js
```

# 5. 安装依赖

项目已经存在：

```text
package-lock.json
```

因此正式构建推荐使用：

```powershell
npm ci
```

而不是：

```powershell
npm install
```

## 为什么推荐 `npm ci`

`npm ci` 会严格按照：

```text
package-lock.json
```

安装依赖。

这样可以尽可能保证：

```text
你的电脑
    │
    ├── npm ci
    ▼
固定版本依赖
```

与：

```text
GitHub Actions
    │
    ├── npm ci
    ▼
固定版本依赖
```

保持一致。

# 6. 最简单的构建方法

直接运行：

```powershell
npm run build
```

当前项目的 `build` 实际执行：

```text
tsc --noEmit --skipLibCheck
```

成功以后继续：

```text
node esbuild.config.mjs production
```

也就是：

```text
TypeScript 类型检查
        ↓

        ↓
main.js
```

# 7. 构建成功后在哪里找 `main.js`

不是：

```text
dist/main.js
```

也不是：

```text
build/main.js
```

而是直接位于仓库根目录：

```text
obu-mindmap/
└── main.js
```

PowerShell 可以检查：

```powershell
Get-Item .\main.js
```

或者：

```powershell
Test-Path .\main.js
```

如果输出：

```text
True
```

说明文件已经生成。

查看文件大小：

```powershell
Get-Item .\main.js | Select-Object Name, Length, LastWriteTime
```

# 8. 推荐：不要只执行 `npm run build`

如果准备生成一个真正用于安装或发布的 `main.js`，推荐运行：

```powershell
npm run check
```

而不是只运行：

```powershell
npm run build
```

因为当前项目：

```text
npm run check
```

相当于：

```text
npm run lint
        ↓
npm run build
        ↓
npm test
```

其中：

```text
npm test
```

又会执行：

```text
npm run test:core
npm run test:persistence
```

因此完整流程是：

```text
ESLint
   ↓
TypeScript 类型检查
   ↓
esbuild production
   ↓
main.js
   ↓
核心测试
   ↓
持久化测试
```

全部通过后，再使用生成的 `main.js` 更稳妥。

# 10. 验证发布版本信息


```text

```

因此：


```text

```

而：

```text

```

负责：

```text

```

两者不是一回事。

# 12. 安装到 Obsidian 进行实际测试

仅仅生成：

```text
main.js
```

还不足以构成一个完整 Obsidian 插件目录。

Obsidian 插件至少需要：

```text
main.js
manifest.json
```

你的插件另外还需要：

```text
styles.css
```

因此建议安装：

```text
main.js
manifest.json
styles.css
```

---

## 插件目录结构

假设 Vault 是：

```text
D:\Obsidian\MyVault
```

插件目录应该是：

```text
D:\Obsidian\MyVault\.obsidian\plugins\obu-mindmap\
```

最终：

```text
MyVault
└── .obsidian
    └── plugins
        └── obu-mindmap
            ├── main.js
            ├── manifest.json
            └── styles.css
```

# 13. PowerShell 一键复制

假设插件仓库位于：

```text
D:\Code\obu-mindmap
```

Vault 位于：

```text
D:\Obsidian\MyVault
```

可以执行：

```powershell
$pluginDir = "D:\Obsidian\MyVault\.obsidian\plugins\obu-mindmap"

New-Item -ItemType Directory -Force $pluginDir

Copy-Item .\main.js $pluginDir -Force
Copy-Item .\manifest.json $pluginDir -Force
Copy-Item .\styles.css $pluginDir -Force
```

然后检查：

```powershell
Get-ChildItem $pluginDir
```

应该看到：

```text
main.js
manifest.json
styles.css
```

# 15. 开发模式和正式构建模式的区别

项目还存在：

```powershell
npm run dev
```

它执行：

```text
node esbuild.config.mjs
```

这属于开发模式。

## 开发模式

```powershell
npm run dev
```

特点：

```text
持续监听源码变化
自动重新生成 main.js
包含 inline sourcemap
不进行生产 minify
```

适合：

```text
写代码
→ 保存
→ 自动构建
→ Obsidian 调试
```

---

## 生产模式

```powershell
npm run build
```

特点：

```text
TypeScript 类型检查
生产构建
无 sourcemap
minify
tree shaking
生成最终 main.js
```

适合：

```text
发布
安装
Release
正式测试
```

因此不要把：

```powershell
npm run dev
```

生成的 `main.js` 当作最终 Release 构建。

正式发布时使用：

```powershell
npm run build
```

或者更推荐：

```powershell
npm run check
```

# 16. 修改代码以后如何重新构建

例如修改：

```text
src/main.ts
```

或者：

```text
src/markdown-file.ts
```

以后，不需要重新：

```powershell
npm ci
```

直接：

```powershell
npm run check
```

即可。

然后新的：

```text
main.js
```

会覆盖仓库根目录原来的：

```text
main.js
```

再复制到 Obsidian 插件目录：

```powershell
Copy-Item .\main.js "D:\Obsidian\MyVault\.obsidian\plugins\obu-mindmap\" -Force
```

如果：

```text
manifest.json
styles.css
```

没有变化，就没有必要每次都复制。

# 17. 日常开发推荐流程

开发代码时：

```powershell
npm run dev
```

保持这个终端运行。

esbuild 会监听源码。

修改：

```text
src/*.ts
```

以后自动生成新的：

```text
main.js
```

开发完成以后终止：

```text
Ctrl + C
```

然后正式执行：

```powershell
npm run check
```

最终流程：

```text
修改源码
   ↓
npm run dev
   ↓
开发测试
   ↓
Ctrl+C
   ↓
npm run check
   ↓
正式 main.js
```
